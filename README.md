# calcwise.by

Бесплатные калькуляторы кредитов: ипотека (готово), дальше кооператив, лизинг и другие виды
кредитования. График платежей считается по банковской методике, поэтому итоги сходятся с
расчётниками банков.

Статический сайт на Astro 7. Сборка — папка с файлами, сервера приложений нет.

## Что нужно

- Node 22.12+
- npm

## Запуск

```bash
npm ci
npm run dev        # http://localhost:4321
```

| `npm run test:coverage` | тесты с порогом покрытия: строки 90%, ветви и функции 85% |
| `npm run lint`          | ESLint с автопочинкой                                     |
| `npm run lint:ci`       | ESLint без починки, предупреждения — ошибка               |
| `npm run format`        | Prettier                                                  |
| `npm run format:check`  | проверка форматирования без правки                        |
| `npm run verify`        | всё, что гоняет CI: формат, линтер, типы, тесты, сборка   |

Перед завершением задачи все четыре должны быть зелёными:

## Проверки в CI

`ci.yml` запускается на каждый push и pull request и делает то же, что `npm run verify`:
форматирование, линтер без автопочинки, типы, тесты с порогом покрытия и только потом сборку.
Превью и боевой деплой выполняют те же шаги перед сборкой, поэтому красный код не выкатится.

## Автоматический деплой

Ветки и что с ними происходит:

| Ветка  | Что запускается  | Куда попадает                                  |
| ------ | ---------------- | ---------------------------------------------- |
| `dev`  | `preview.yml`    | превью на GitHub Pages, закрытое от индексации |
| `main` | `production.yml` | боевой сайт на domain.by через SSH + `rsync`   |

Боевой деплой собирает, прогоняет `check`, `lint` и `test`, выгружает только изменившиеся
файлы и проверяет живой сайт: главная открывается, http отдаёт 301 на https, несуществующая
страница — 404. `.well-known` и `cgi-bin` из синхронизации исключены — иначе
`rsync --delete` снёс бы их вместе с автопродлением SSL.

Пока не задана переменная `DEPLOY_ENABLED=true`, боевой прогон пропускается.

Превью на GitHub Pages работает только из репозитория вида `<владелец>.github.io`: сайт
рассчитан на корень домена, в подпути `github.io/<repo>/` абсолютные пути к шрифтам, иконкам
и меню сломаются. В обычном репозитории превью просто пропускается.

### Разовая настройка

1. Запросить SSH у `support@domain.by` письмом с контактного адреса хостингового аккаунта.
2. Создать ключ и положить публичную часть на хостинг в `~/.ssh/authorized_keys`:

   ```bash
   ssh-keygen -t ed25519 -f ~/.ssh/calcwise_deploy -C "github-actions" -N ""
   ```

3. Добавить секреты в Settings → Secrets and variables → Actions → Secrets:
   `SSH_PRIVATE_KEY` (содержимое файла без `.pub`), `SSH_HOST`, `SSH_PORT`, `SSH_USER`.
4. Там же на вкладке Variables добавить `DEPLOY_ENABLED` = `true`.
5. Проверить `DEPLOY_PATH` в `production.yml`: путь к корню сайта на хостинге.
6. Для превью: Settings → Pages → Source → GitHub Actions.
7. Settings → Environments → `github-pages` → Deployment branches → добавить `dev`.
   GitHub создаёт это окружение сам и разрешает деплой только с ветки по умолчанию, а
   превью идёт с `dev`: без этого шага деплой отказывает с ошибкой protection rules.

Если нужен ручной контроль над выкатом — Settings → Environments → `production` →
Required reviewers: Actions соберёт сайт и остановится, ожидая подтверждения.

Всё поведение сервера лежит в `public/.htaccess`: http → https, www → без www, завершающий
слеш, заголовки безопасности, кэш. Файл читают только Apache и LiteSpeed. Переименовали или
удалили страницу — добавьте 301 туда, других копий карты редиректов нет.

## Ручная выкладка

```bash
npm run build
cd dist && zip -r ../calcwise.zip . -x '.DS_Store' '*/.DS_Store'
```

Архив распаковать в корень сайта; точка после `-r` забирает и скрытый `.htaccess`.
